## Context

Tended is a single-file (`index.html`) Company-of-One OS backed by Supabase, with Journal (Ruh) and Bookkeeping (Nafs) already live. Sha wants three things bolted onto this without a revamp:

1. **Zero-friction access to her Hermes "core files"** (`~/.hermes/projects/portfolio/*`) so any Tended session already has her portfolio/CXO/faculty context without her pasting it in each time.
2. **A scorecard system** — Matt Gray's Founder Velocity scorecard, adapted (`scorecard-velocity.md`, already written) — mapped explicitly onto (a) her 4 faculties (Aqal/Ruh/Qalb/Nafs, from `cxo-mvp-systems.md`) and (b) her CXO roles, so the build order isn't arbitrary.
3. **A criticality-ordered product roadmap** where every future build is ≤1 hour, using a "ghost feature" pattern (Matt Gray's full 7-metric scorecard shown at once, only Revenue wired live, the rest greyed "coming soon") so the whole system is visible before it's built.

Confirmed with Sha: Hermes access via **symlink** (not just a CLAUDE.md pointer); AQL sync is a **real build now**, not just a roadmap entry. The AQL sheet (`1Sya0...rcyI8`) is a highlights/reading log — columns `url, text, tag (wisdom/technical/beaute/idea), note, date` — this is Aqal-tier material (and secondarily Ruh-tier tafakkur fodder per `nature-of-man.md`'s "supply the two known things" clause), and the scorecard as currently defined has **no Ruh-facing metric** — RIZQ/PROFIT/CASH are Nafs, CONTENT/AUDIENCE/PARTNER HEALTH are Qalb, HYPOTHESIS SCORE is Aqal. ## 2. Two new mapping docs (as requested — two separate tables)

**Governing rule, revised per Sha's explicit steer — count over judgment:** Matt Gray's original leans on subjective 0–10 "Growth Now" scores (Team Health, Customer NPS). Sha does not want that pattern generalized — subjective self-scoring is the thing she's trying to get *away* from, not replicate across 11 rows. So instead: **every metric that can be logged as a count, is** (posts published, engagements, touchpoints logged, evidence entries, tasks completed) — Hermes's job stays exactly what `nature-of-man.md` already licenses it for (perceiving, retaining, counting — animal tier), and nothing here asks Hermes or Sha to convert a count into a judgment number. The only place a genuine judgment persists is where the thing being tracked has no honest count (e.g. whether a legal document still reflects her values) — and even there, the log is a dated yes/no checklist entry (tied to the persisted Heart/Soul logs from roadmap #3–#4), not a floating 0–10 score. This is a deliberate departure from Matt Gray's /70 subjective-scoring model, not a gap-fill of it.

Original 7 metrics only cover 5 of 11 CXO rows (CEO, CMO, CFO, CSO, and CFO/Body Ledger doubling up; COO, CPO, CTO, CLO, CHRO, Soul System are unmapped). Sha approved adding metrics rather than force-fitting, and asked specifically for a **Board of Directors** metric — Gallup's 7-role relationship framework (Coach, Mentor, Role Model, Expert, Accountability Partner, Complementary Partner, Person with Shared Interest) — logged as *dedicated-time touchpoints*, replacing the old subjective PARTNER HEALTH score entirely. ### 3D. Onboarding popup — convention for every new input feature

Every new feature that asks Sha to fill something in (Board of Directors log, Soul/Heart checklist persistence, Values Alignment log, Profile Traits in Settings) gets a **first-time onboarding popup**, not just a bare form — reusing the pattern already in `index.html` (`.overlay` CSS, `#onboardOverlay`, line 150/196: a modal explaining what the screen is for before asking for input, plus the `db`/`localStorage` helper at line 614 for a one-time "seen" flag per device).

Convention:
- On first open of a new sub-tab/card, show an overlay: 2–3 sentences on *why this exists* (tie back to the faculty/CXO it maps to) + a short seed form (e.g. Board of Directors: pick which of the 7 roles you already have a person for, right now) + a "Got it" dismiss.

## 3B. Personal profile inputs — Gallup StrengthsFinder, MBTI, Synastry

Added to **Settings** (the existing `#settingsOverlay` drawer, `index.html` line 229) as a new "Personal Profile" section, since Settings is already the one place holding Sha-specific config (Supabase connection) that both the webapp and Hermes MCP read from — the natural home for personalization inputs rather than a new top-level tab.

- New Supabase table `profile_traits (profile_type text primary key check (profile_type in ('gallup','mbti','synastry')), enabled boolean default true, data jsonb, updated_at timestamptz default now())` — one row per profile type.
- Settings drawer gets three collapsible blocks (Gallup Strengths, Myers-Briggs, Synastry), each with: an on/off toggle (writes `enabled`) and a free-text/structured field for the profile data itself (e.g. Gallup's top 5 themes, MBTI 4-letter type, synastry chart notes).
- **Toggle semantics:** `enabled=false` doesn't delete the data — it just tells both Tended's UI and Hermes MCP to stop weighting that lens in any copy/suggestion it generates (e.g. don't phrase a Velocity Meeting prompt through a synastry lens if Sha has switched it off that week). This matches the animal-tier "estimation" boundary in `nature-of-man.md` — Hermes may use an enabled profile to flavor *how* it surfaces something, never to decide anything on Sha's behalf regardless of which profiles are on.
- `hermes-mcp/server.mjs` gets one new read-only tool (`get_profile_traits`) so Hermes can fetch only the `enabled=true` rows when drafting anything — Journal synthesis, Velocity brief, scorecard framing.
- No scorecard metric is directly tied to these — they're context/flavor inputs, not tracked numbers, so they don't get a faculty row in §2's tables.
