# Tended.Today — Company of One OS (MVP)

One database (Supabase), three surfaces:

| Surface | Who uses it | What it does |
|---|---|---|
| `index.html` | Sha | Dashboard + Money + Time + Heart. Onboarding connects it to Supabase, magic-link login gates it. |
| Supabase REST API | Any app you build later | Auto-generated by Supabase for every table (`/rest/v1/transactions`, etc.) |
| `hermes-mcp/` | Hermes / Hannachan | MCP tools with Trust Ladder guardrails baked in |

## Setup order (≈15 minutes)

**1. Create the database**
- supabase.com → New project (free tier is fine, pick Singapore region)
- SQL Editor → paste `schema.sql` → Run (this now includes the Heart module table)
- Already ran an older `schema.sql`? Just run `schema-heart.sql` to add the Heart table.
- Settings → API → copy the **Project URL** and the **anon public key**

**2. Launch the webapp**
- Open `index.html` in your browser (or upload to Hostinger — it's one file)
- The onboarding screen asks for the URL + anon key, tests the connection, and remembers it on this device
- No Supabase yet? Choose **Explore in demo mode** — everything works in-memory so you can feel the flow first

**3. Connect Hermes (MCP)**
```bash
cd hermes-mcp
npm install
```
Add to Hermes' MCP config (or Claude Desktop's `claude_desktop_config.json`):
```json
{
  "mcpServers": {
    "tended-today": {
      "command": "node",
      "args": ["/absolute/path/to/hermes-mcp/server.mjs"],
      "env": {
        "SUPABASE_URL": "https://YOURPROJECT.supabase.co",
        "SUPABASE_SERVICE_KEY": "your-service-role-key"
      }
    }
  }
}
```
The **service_role key** lives only here, server-side. Never put it in the webapp.

## Deploy live on Cloudflare Pages

It's one static file, so no build step.

**Option A — dashboard (recommended):**
1. Cloudflare → **Workers & Pages** → **Create** → **Pages** → **Connect to Git** → pick `webdevsha/tended`.
2. Build settings: **Framework preset:** None · **Build command:** *(leave empty)* · **Build output directory:** `/`.
3. Deploy. You get a URL like `https://tended.pages.dev`.

**Option B — CLI:** `npx wrangler pages deploy . --project-name tended`

Nothing secret goes on Cloudflare — the Supabase URL + anon key are entered in-app (onboarding) and stored per-device. The anon key is public by design; the magic-link login (below) is what protects your data.

### Point Supabase at the deployed URL (for magic links)
Supabase → **Authentication** → **URL Configuration**:
- **Site URL:** your Pages URL (e.g. `https://tended.pages.dev`)
- **Redirect URLs:** add the same URL (and any custom domain).

## Auth — single-user magic link

1. First load asks for your Supabase URL + anon key, then sends a **magic link** to your email. Click it → you're in. The session persists on the device.
2. **Harden before sharing the URL anywhere:**
   - Supabase → **Authentication** → **Users** → invite your own email.
   - Supabase → **Authentication** → **Sign In / Providers** → disable new sign-ups so only you can log in.
   - Run `schema-auth.sql` to swap the permissive MVP policies for **authenticated-only** RLS. After this, a visitor with the public anon key still can't read anything without logging in.
- Sign out anytime from **Settings**.

## Trust Ladder — encoded, not aspirational

| Action | Sha (webapp) | Hermes (MCP) |
|---|---|---|
| Read all data | ✅ | ✅ |
| Add transactions, time blocks, PLC logs | ✅ | ✅ |
| Create invoice | ✅ any status | ✅ **draft only** |
| Mark invoice **sent** / paid | ✅ | ❌ — tool schema excludes it |
| Journal entries | ✅ approved | ✅ **draft** (`approved=false`), Sha approves in webapp |
| Heart / connection logs | ✅ | ✅ (`log_heart`) |

## REST API contract (for future webapps / PolyFlow-style integrations)

Supabase auto-exposes every table. Examples with the anon key:

```
GET  {SUPABASE_URL}/rest/v1/transactions?tx_date=gte.2026-07-01
POST {SUPABASE_URL}/rest/v1/invoices        (body: {client, amount, status:"draft"})
GET  {SUPABASE_URL}/rest/v1/time_blocks?block_date=gte.2026-06-29&is_work=eq.true
```
Headers on every call: `apikey: <anon-key>` and `Authorization: Bearer <anon-key>`.

## What's live now

- **Auth:** magic-link login (single-user). Harden with `schema-auth.sql` + disabled sign-ups before sharing the URL.
- **Money (Body):** transactions, invoices (Trust-Ladder statuses), and statements.
- **Statements beyond cash-basis:** P&L (cash) plus a balance sheet with assets = cumulative net + accounts receivable, and an **equity-movement audit trail** (opening → +net → closing → +receivable = owner's equity today). Every line traces to a dated, sourced row.
- **Time (Mind) — Module 2 v2:** manual + Hermes logging with the Pareto guard. Plus a **manual `.ics` import** in Settings (export a day/week from Google Calendar → events become time blocks). Full GCal auto-sync stays a labeled v2.
- **Heart (Qalb) — measurable & live:** log moments of connection (Mama practice / check-in with R / family / self-compassion), with a weekly "tended" count and a day-streak. Gentle by design.
