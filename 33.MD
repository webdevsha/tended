## 3. Brevo automation chain (weekly emails)

This is done **entirely in Brevo** — no worker changes needed for the sequence.

### Step-by-step in Brevo:

**a) Create a dedicated contact list**
Contacts → Lists → Create list → name it `ThirtyThree`
Copy the numeric ID (you'll need it as `BREVO_LIST_ID`).

**b) Create the automation**
Automations → Create workflow → "Contact added to a list" trigger

Set trigger: Contact added to list `ThirtyThree`

**c) Build the email sequence**

```
[Trigger: added to ThirtyThree list]
    │
    ├── Wait: 0 min
    │   └── [Welcome email is sent by the worker transactionally — skip here]
    │
    ├── Wait: 7 days
    │   └── Send email: Issue 01 — "The four fundamentals of good character"
    │
    ├── Wait: 7 days
    │   └── Send email: Issue 02 — "Menefregismo and the Muslim professional"
    │
    ├── Wait: 7 days
    │   └── Send email: Issue 03 — "Thirty-three: not a deadline"
    │
    └── [continue weekly...]
```

**d) Weekly new issues**
For ongoing weekly sends after the drip sequence ends:
Campaigns → Email campaigns → Create → Schedule weekly to the `ThirtyThree` list.

## 4. How the full flow works

```
User fills form on thirtythree.html
    │
    ▼
Worker ACTION: subscribe_newsletter
    → Adds contact to Brevo list (BREVO_LIST_ID)
    → Brevo automation trigger fires (drip sequence starts)
    │
    ▼
Worker ACTION: send_email (items_purchased = 'thirtythree_welcome')
    → Sends immediate welcome email via Brevo transactional API
    │
    ▼
Brevo automation (7 days later)
    → Sends Issue 01
    → Sends Issue 02 (14 days after signup)
    → ...continues weekly
```

The welcome email is **transactional** (sent instantly by the worker).
The drip sequence is **automation** (handled entirely by Brevo).
They don't conflict — Brevo deduplicates sends.
